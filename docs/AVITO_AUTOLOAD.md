# Интеграция Авито: автозагрузка XLSX

## Назначение

В приложении на странице **Настройки → Интеграция** (`/settings/integration`) можно:

- сохранить **Client ID**, **Client secret** и **ID пользователя Авито** для вашей организации (данные хранятся в БД; секрет шифруется);
- загрузить файл **автозагрузки** в формате **.xlsx** (как в личном кабинете Авито);
- получить **локальную проверку** структуры и обязательных полей;
- при успешной настройке ключей — отправить файл в **API Авито** (`POST /autoload/v1/upload`) и увидеть JSON-ответ и при доступности — последний отчёт автозагрузки.

Файлы на диске сервера: `backend/uploads/avito/<id_организации>/<имя>_<uuid>.xlsx`. При каждой новой загрузке предыдущие `.xlsx` в этой папке удаляются — **хранится только один актуальный файл**.

Снимок последней разобранной выгрузки (строки для таблицы и метаданные проверки) хранится в БД в таблице `organization_avito_autoload_cache`. SQL для создания: `backend/migrations/add_organization_avito_autoload_cache.sql`.

## Где взять ключи API

1. Зарегистрируйте приложение в [портале разработчика Авито](https://developers.avito.ru/).
2. Получите **client_id** и **client_secret** для доступа к API (тип авторизации: OAuth2, в т.ч. `client_credentials`).
3. **ID пользователя Авито** — числовой идентификатор аккаунта в ЛК Авито; он нужен для методов автозагрузки и отчётов.

В продакшене задайте отдельный ключ шифрования секретов в окружении сервера:

- `AVITO_CREDENTIALS_SECRET` — произвольная длинная строка (если не задана, для шифрования используется `SECRET_KEY` приложения, что хуже с точки зрения изоляции секретов).

## Правила файла автозагрузки (шаблон Авито)

Типовой файл содержит:

1. **Лист с инструкцией** — текстовые правила; его не нужно менять для выгрузки данных.
2. **Один или несколько листов категорий** — в каждом:
   - **Строка 1** — полное название категории (не удалять и не менять).
   - **Строка 2** — имена параметров (заголовки колонок).
   - **Строка 3** — обязательность: «Обязательный», «Может быть обязательным», «Необязательный».
   - **Строка 4** — подсказка по формату значения.
   - **С строки 5** — строки объявлений.

Важно:

- не добавляйте новые листы без необходимости (это может ломать проверку на стороне Авито);
- не удаляйте и не сдвигайте строки 1–4 на листе категории;
- не меняйте вручную служебные поля вроде статусов выгрузки, если они есть в шаблоне скачанного файла.

## Какие колонки показываются в таблице на сайте

Из каждого листа-категории (где во 2-й строке есть колонка «Название объявления») в таблицу попадают:

| Колонка в интерфейсе | Поле в XLSX        |
|----------------------|--------------------|
| Номер детали (OEM)   | «Номер детали OEM» или «Номер детали» |
| Производитель        | «Производитель»    |
| Состояние            | «Состояние»        |
| Цена                 | «Цена» (целое число) |
| Название объявления  | «Название объявления» |

## Локальная проверка

Бэкенд проверяет:

- наличие на листе ключевых колонок (название, цена, состояние);
- заполнение всех колонок, помеченных в строке 3 как **«Обязательный»**;
- что **цена** в данных строках преобразуется в **целое число**.

Полная семантика «Может быть обязательным» зависит от условий Авито по категории — при необходимости ориентируйтесь на комментарии в ячейках шаблона и [документацию автозагрузки](https://www.avito.ru/autoload/documentation).

## Поведение при загрузке на сервер

1. Файл сохраняется в `uploads/avito/<org_id>/` (старые XLSX в каталоге перед этим удаляются).
2. Выполняется разбор и локальная валидация.
3. Если для организации сохранены ключи Авито, запрашивается OAuth-токен, затем вызывается загрузка файла в API; в ответ страница показывает HTTP-код и тело ответа (если есть).
4. Дополнительно запрашивается последний завершённый отчёт (`/autoload/v3/reports/last_completed_report`) или, при недоступности, отчёт через v1 с вашим `user_id`.

Если ключи не настроены или произошла ошибка авторизации в Авито, файл всё равно сохраняется и отображаются результаты **локальной** проверки и таблица товаров.

## Статус работы автозагрузки

На текущий момент автозагрузка **работает**:

- загрузка `.xlsx` файла в систему работает;
- отправка файла в Avito API после загрузки работает (при валидных ключах);
- массовые действия из модалки (`Опубликовать объявление`, `Снять с публикации`, `Удалить объявление`) работают через обновление файла и повторную отправку в Avito API.

Ограничение для действий:

- если на листе категории в строке заголовков (строка 2) нет колонки `Действие` (или `Action`), backend вернёт `400 Bad Request`.
- если не выбраны строки для действия, backend вернёт `400 Bad Request`.

## Безопасность

- Не публикуйте **client_secret** в репозитории и не пересылайте в открытых каналах.
- При компрометации ключа выпустите новый в кабинете разработчика Авито.
