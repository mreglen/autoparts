# Laximo.CAT API — пригодность для поиска по VIN

Оценка по официальной документации [doc.laximo.ru](https://doc.laximo.ru/) (сервис **Laximo.CAT** — оригинальные каталоги запчастей).

План внедрения в сайт (гараж, разборка, поиск по VIN, методы REST РФ): [laximo-cat-integration-plan.md](./laximo-cat-integration-plan.md).

**Поэтапный план для Plan mode** (прикрепляй в чат → «сделай план для этапа N»): [laximo-stages-plan.md](./laximo-stages-plan.md).

**Краткий вердикт:** для трёх целевых сценариев (VIN → авто, VIN → запчасти, VIN → узлы вроде «двигатель / ходовая») функционала **CAT в целом хватает**. Это OEM-каталог с навигацией по узлам, а не универсальный VIN-декодер и не витрина склада с ценами/наличием.

Источники: [Поиск автомобиля](https://doc.laximo.ru/ru/cat/vehicle), [FindVehicle](https://doc.laximo.ru/ru/cat/FindVehicle) / [FindVehicleByVIN](https://doc.laximo.ru/ru/cat/FindVehicleByVIN), [GetVehicleInfo](https://doc.laximo.ru/ru/cat/GetVehicleInfo), [Поиск внутри автомобиля](https://doc.laximo.ru/ru/UseCases/SearchInsideTheCar), [ListCategories](https://doc.laximo.ru/ru/cat/ListCategories) / [ListUnits](https://doc.laximo.ru/ru/cat/ListUnits) / [ListDetailByUnit](https://doc.laximo.ru/ru/cat/ListDetailByUnit).

## 1. Целевые сценарии

| # | Сценарий | Покрытие CAT |
|---|----------|--------------|
| A | Поиск запчастей по VIN | **Да** (OEM-артикулы через каталог после идентификации авто) |
| B | Информация об авто по VIN (марка, модель, кузов и т.д.) | **Да, с оговорками** (набор полей зависит от каталога) |
| C | По VIN — дерево узлов (двигатель, ходовая и т.д.) | **Да** (категории + узлы; опционально quick groups) |

## 2. Что есть в API под эти задачи

### 2.1. Идентификация автомобиля по VIN

| Метод | Назначение |
|-------|------------|
| `FindVehicle` | Поиск по VIN **или** Frame (REST и SOAP). Каталог можно не указывать — сервис сам подберёт. |
| `FindVehicleByVIN` | Специализированный поиск по VIN (**только SOAP**). |
| `FindVehicleByFrame` / `FindVehicleByFrameNo` | Японский рынок: код/номер кузова вместо VIN. |
| `FindVehicleByPlateNumber` | По госномеру (если доступно в тарифе/каталоге). |
| `ListCatalogs` / `GetCatalogInfo` | Флаги возможностей каталога: `vinsearch`, `framesearch`, `wizardsearch2`, `quickgroups`, `fulltextsearch`. |

**Что возвращает поиск по VIN (типично):**

- `brand` — производитель  
- `name` — наименование авто (часто модель / поколение)  
- `catalog` — код каталога  
- `vehicleId` — id авто в каталоге  
- `ssd` — серверное состояние сессии (обязательно тащить дальше по цепочке)  
- `attributes` — доп. параметры (модель, кузов, двигатель, КПП, год и т.п. — **не фиксированный набор**)  
- `sysProperties` (например `filter_level`) — точность идентификации  

Без предварительного выбора каталога поиск по VIN/Frame **поддерживается**; один VIN может дать несколько кандидатов (разные регионы/каталоги/модификации).

### 2.2. Карточка автомобиля (марка, модель, кузов…)

| Метод | Назначение |
|-------|------------|
| Ответ `FindVehicle` / `FindVehicleByVIN` | Уже содержит brand/name + attributes; для гаража Laximo рекомендует именно VIN/Frame, а не wizard. |
| `GetVehicleInfo` | Расширенная/общая карточка по `catalog` + `vehicleId` + `ssd`. |

**Примеры атрибутов из документации** (могут быть или отсутствовать в конкретном каталоге):

- `model`, `modification`, `description`, `grade`  
- `frame` / `frames` / `framefrom`–`frameto` — кузов  
- `engine` / `engine_info` / `engineno`  
- `transmission`, `doors`  
- `manufactured`, `date`, `modelyearfrom` / `modelyearto`, `prodrange`  
- `framecolor`, `trimcolor`  
- `market`, регионы производства/поставки, `options`  

С `Localized=true` названия атрибутов приходят на нужном языке (например `ru_RU`).

### 2.3. Узлы и запчасти после VIN (сценарий C + A)

Типовой поток:

```
VIN
 → FindVehicle / FindVehicleByVIN
 → (при необходимости GetVehicleInfo)
 → ListCategories          # дерево: двигатель, ходовая, кузов…
 → ListUnits               # узлы внутри категории
 → GetUnitInfo             # карточка узла + схема
 → ListDetailByUnit        # OEM-детали узла
 → ListImageMapByUnit      # кликабельные зоны на схеме (опционально)
```

Альтернатива «быстрые группы» (если у каталога есть feature `quickgroups`):

```
VIN → … → ListQuickGroup → ListQuickDetail
```

Дополнительно внутри уже выбранного авто:

| Метод | Назначение |
|-------|------------|
| `SearchVehicleDetails` | Поиск деталей по названию (нужен feature `fulltextsearch`) |
| `GetOEMPartApplicability` | Применимость известного OEM к этому авто |
| `GetFilterByDetail` | Уточнение применимости, если у детали есть `filter` |

Итог по запчастям: **OEM-номера, наименования, схемы узлов**, фильтрация под конкретный VIN через `ssd`.

## 3. Чего не хватит / ограничения

### 3.1. Не универсальный «VIN-декодер»

- Набор полей **не стандартизирован**: в одном каталоге будет `frame` + `engine_info`, в другом — только `model` и годы.
- Нельзя рассчитывать на стабильные «марка / модель / тип кузова / год» в одной схеме для всех брендов — нужна своя нормализация `attributes` → поля гаража.
- Один VIN → несколько строк: нужна UI-логика выбора кандидата.
- Не все каталоги поддерживают `vinsearch` — проверять через `ListCatalogs` / `GetCatalogInfo`.
- Японские авто часто идут через **Frame**, не VIN.
- Это данные **оригинального каталога**, не ГИБДД / не ПТС: нет владельца, СТС, пробега, ДТП и т.п.

### 3.2. Запчасти — только OEM-каталог, не ваш склад

CAT **не даёт**:

- цены и наличие вашего магазина / Rossko / Avito;  
- автоматический кросс OEM → aftermarket (для этого отдельные продукты вроде **Laximo.DOC** / Search — уточнять в договоре);  
- «корзину запчастей под VIN» без собственной связки OEM ↔ товары в БД.

Для витрины нужно: OEM из CAT → матчинг по артикулу в вашем каталоге/поставщиках.

### 3.3. Узлы «двигатель / ходовая» — не фиксированная таксономия

- Иерархия категорий **зависит от OEM-каталога** (названия и глубина разные у Toyota, VW, Peugeot…).
- `quickgroups` есть **не у всех** каталогов.
- Без `ssd` + `vehicleId` + `catalog` навигация по узлам невозможна — состояние сессии обязательно хранить.
- У части деталей будет `filter` → нужны доп. шаги уточнения применимости.

### 3.4. Продуктовые / интеграционные пробелы вне CAT

| Нужно продукту | Есть в CAT? |
|----------------|-------------|
| Fallback, если VIN не найден | Нет → wizard (`GetWizard2` + `FindVehicleByWizard2`) или ручной ввод (как в roadmap гаража) |
| Единый справочник марок/моделей для фильтров сайта | Нет → своя БД или нормализация |
| Поиск «все запчасти в наличии под VIN» одним запросом | Нет → обход каталога + матчинг склада |
| Лицензия: какие бренды/каталоги открыты | Зависит от договора с Laximo, не от наличия метода в API |
| REST для `FindVehicleByVIN` | Нет (только SOAP); для REST — `FindVehicle` |

### 3.5. Качество подбора

По документации Laximo: подбор по **параметрам (wizard)** даёт **меньше точности**, чем VIN/Frame — в гараж такие авто класть не рекомендуют. Для сценариев A–C приоритет — VIN/Frame.

## 4. Соответствие сценариям — итог

### A. Поиск запчастей по VIN — **подходит**

Есть полный OEM-пайплайн: VIN → авто → категории/группы → узлы → детали (`oem`, name, схемы).

**Достроить самим:** матчинг OEM к складу/поставщикам, цены, корзина, кэш `ssd`/сессии.

### B. Инфо об авто по VIN — **подходит с оговорками**

Brand/name + богатый, но **нестабильный** набор attributes (модель, кузов, двигатель, год…).

**Достроить самим:** маппинг атрибутов под поля гаража, выбор из нескольких кандидатов, fallback без VIN, проверка `supportvinsearch` по каталогам в лицензии.

### C. Узлы по VIN (двигатель, ходовая…) — **подходит**

`ListCategories` + `ListUnits` (+ `ListQuickGroup` где доступно) — ровно сценарий «ввёл VIN → увидел узлы».

**Достроить самим:** единый UX поверх разных деревьев OEM, кэш иллюстраций, обработка `filter`/уточнений.

---

## 5. Минимальный набор методов для MVP

1. `ListCatalogs` — понять покрытие и features.  
2. `FindVehicle` (REST) или `FindVehicleByVIN` (SOAP) — VIN → авто.  
3. `GetVehicleInfo` — добрать карточку при необходимости.  
4. `ListCategories` → `ListUnits` → `GetUnitInfo` → `ListDetailByUnit` — узлы и детали.  
5. Опционально: `ListQuickGroup` / `ListQuickDetail`, `SearchVehicleDetails`.

---

## 6. Практическая рекомендация

**Laximo.CAT достаточно** как ядро OEM-каталога по VIN (информация об авто + дерево узлов + OEM-запчасти).

Его **недостаточно в одиночку**, если нужны:

- гарантированно полная карточка авто для гаража на любом бренде;  
- aftermarket-кроссы и цены;  
- поиск «что есть на складе под этот VIN» без своей связки артикулов.

Оптимальная схема для продукта: **CAT по VIN** → нормализованная карточка авто + OEM → **ваш склад / поставщики** по артикулу; при отсутствии VIN — wizard или ручной ввод.
