Деплой на продакшен (`scripts/deploy/update.sh` → `sudo update` на сервере). Строго по шагам:

1. `git status` и `git log origin/<branch>..HEAD` — проверь состояние. Если есть незакоммиченные файлы или незапушенные коммиты — **не останавливайся**: сначала создай коммит со всеми изменениями (`git add -A` + осмысленное сообщение про «почему»), затем `git push origin <branch>`, и только после этого переходи к деплою. Исключение: явно чужие/неожиданные изменения — спроси перед включением в коммит.
2. Опции деплоя: `--frontend-only`, `--backend-only`, `--skip-frontend`, `--skip-backend`, `--rollback`. Если пользователь не указал опции — по умолчанию запускай обычный `sudo update` без флагов, не спрашивай.
3. Покажи точную команду перед запуском. Если доступа до сервера нет (SSH не настроен) — дай команду пользователю для ручного запуска и продолжи с шага 4 после его подтверждения.
4. После деплоя — health-checks по AGENTS.md §5.4: `systemctl is-active kroan.service`, `celery.service`, curl `https://svoygarage.ru/server/api/auth/public-site-config`, попросить пользователя нажать Ctrl+F5.

НИКОГДА не деплой без явной команды пользователя на деплой. НИКОГДА не запускай `update`/`update.sh` локально — только на сервере через sudo.
