# План: Экспорт в Avito autoload.xlsx по готовому шаблону

## 1. Зафиксировать структуру шаблона

- Использовать существующий файл `[backend/uploads/avito/qMHbBIoD51/autoload.xlsx](backend/uploads/avito/qMHbBIoD51/autoload.xlsx)` как *единственный* источник структуры:
  - Не создавать свои `_EXPORT_HEADERS` и `_MANDATORY_HEADERS` произвольно.
  - При первом экспорте всегда загружать этот файл, а не генерировать новый workbook.
- В модуле `[backend/app/services/avito_autoload_xlsx.py](backend/app/services/avito_autoload_xlsx.py)`:
  - Обновить вспомогательные функции так, чтобы они ориентировались на уже существующие заголовки из второй строки шаблона, в частности:
    - `"Уникальный идентификатор объявления"` (col 1)
    - `"Номер объявления на Авито"` (col 3)
    - `"Название объявления"`, `"Описание объявления"`, `"Ссылки на фото"`, `"Название фото"`, `"Категория"`, `"Вид товара"`, `"Тип товара"`, `"Вид объявления"`, `"Состояние"`, `"Цена"`, `"Количество модулей в комплекте"`, `"Целевая аудитория"`, `"AvitoStatus"` и др.
  - Обновить `_find_col_map` и поиск колонок, чтобы они находили эти русские заголовки по точному имени, а не через старые константы (`PART_OEM`, `PRODUCT_ID_HEADER` и т.п.).

## 2. Поле "Уникальный идентификатор объявления" и номер объявления на Авито

- В `upsert_products_to_avito_autoload`:
  - Ввести использование двух ключевых идентификаторов:
    - `unique_ad_id` — значение для колонки `"Уникальный идентификатор объявления"` (col 1). Источник: брать `product.internal_code` (как договорились), а если его нет — генерировать новый код того же формата (`00001`..), но **не записывать его в базу**, только в Excel.
    - `avito_ad_number` — значение для колонки `"Номер объявления на Авито"` (col 3). Это поле мы **не заполняем при экспорте** (оставляем пустым, чтобы Авито вернул значение при загрузке).
  - При поиске существующих строк в Excel для апдейта использовать комбинацию:
    - сначала совпадение по `unique_ad_id` (колонка 1),
    - затем по `AvitoId` (если где-то встречается, совместимость со старым форматом),
    - затем по бизнес-ключам (артикул и т.п.), как сейчас.
  - При записи строки строго заполнять:
    - col 1: `product.internal_code`
    - col 3: пусто (или существующее значение, если строка уже была и мы не хотим его затирать)

## 3. Заполнение обязательных колонок по шаблону

- Для каждого листа (категории) в `upsert_products_to_avito_autoload`:
  - При инициализации контекста листа (`_get_sheet_ctx`) дополнительно прочитать пример строки (обычно 5-я строка) и сохранить **дефолтные значения** всех обязательных колонок этого листа.
  - При создании новой строки для товара заполнять колонки так:
    - Поля, конкретно зависящие от товара: `Название объявления`, `Описание объявления`, `Цена`, `Адрес` (из `storage_location.address` + `organization.address` если нужно), `Фото` (`Ссылки на фото`), `Количество модулей` (можно 1 или фактическое количество, по бизнес-логике).
    - Остальные обязательные поля, которые в шаблоне заполнены дефолтом (`Вид товара`, `Тип товара`, `Вид объявления`, `Целевая аудитория` и т.п.), брать из примера строки листа, чтобы ваш файл выглядел так же, как образец.
  - Следить, чтобы после заполнения все колонки, где в 3-й строке стоит "Обязательный", имели непустые значения (либо от товара, либо из дефолта).

## 4. Работа с несколькими листами и категориями

- Логику выбора листа оставить на базе `_find_matching_sheet` + `_choose_template_sheet`:
  - Для каждого продукта вычислять строковое имя категории `category = _map_avito_category(product)`.
  - Пытаться найти существующий лист в текущем `autoload.xlsx` по частичному совпадению имени (как уже реализовано).
  - Если нет подходящего листа, можно:
    - либо создать *новый* лист по образцу (копируя заголовки и требования из уже существующего справочного листа этой категории `Спр-*`),
    - либо (проще для первого шага) использовать один уже существующий профильный лист, который вы используете в примере, и не создавать новые листы автоматически.
- В планах на первый шаг: ориентироваться на существующие листы из файла `autoload.xlsx` и не создавать листы с нуля, пока это не потребуется.

## 5. Экспорт (API и Celery задачa)

- В `[backend/app/routers/avito_integration.py](backend/app/routers/avito_integration.py)` и `[backend/app/tasks/avito_tasks.py](backend/app/tasks/avito_tasks.py)`:
  - Убедиться, что `export_rows` передают в `upsert_products_to_avito_autoload` все необходимые поля:
    - `id` (product.id)
    - `internal_code` (если нужно отдельно, либо использовать его внутри `upsert_*`, обращаясь к БД в новой сессии)
    - `article`, `brand`, `is_new`, `price`, `name`, `description`, `quantity`, `photos`, `avito_id`, `category`.
  - При асинхронном экспорте (`run_avito_export_job`) дополнительно передавать `template_sheet`, если он определён `_choose_template_sheet`, чтобы `upsert_*` при необходимости выбирал нужный лист.
  - Обновить сигнатуру `upsert_products_to_avito_autoload` **только внутри backend**, не ломая вызовы снаружи (добавить новые поля в `products[]` аккуратно, без изменения имени функции).

## 6. Импорт и связь с товарами

- В `import_avito_autoload_rows` (`/avito/autoload/import`):
  - При создании нового товара уже используется `_next_internal_code` для заполнения `Product.internal_code` — это соответствует требованию иметь уникальный идентификатор объявления.
  - В части, где создаются `ProductPhoto` из `item["photos"]`, ничего менять не нужно: мы уже будем экспортировать `Ссылки на фото` в корректном виде.
  - Проверить, что привязка по `AvitoId`/`ProductAvitoListingLink` остаётся рабочей (мы не трогаем поле `AvitoId` в шаблоне, оно используется только для связи).

## 7. Валидация и контроль соответствия образцу

- В тестовом режиме:
  - Запустить экспорт для пары товаров через `/api/organizations/{org_id}/avito/autoload/export`.
  - Открыть обновлённый `[backend/uploads/avito/qMHbBIoD51/autoload.xlsx](backend/uploads/avito/qMHbBIoD51/autoload.xlsx)` и сравнить:
    - Заголовки строк 1–4 по каждому листу с вашим исходным файлом (должны совпадать 1:1).
    - Что в строках данных все обязательные поля заполнены и визуально выглядят так же, как пример из Авито-документации (ваши скриншоты).
  - Запустить `parse_and_validate_avito_autoload` на новом файле и убедиться, что `local_ok=True` и список `local_errors` пустой.

## 8. Риски и дальнейшие улучшения

- Учесть, что ваш текущий файл уже содержит примерные объявления; при первом же экспорте мы будем либо обновлять существующие строки (по `internal_code`/`AvitoId`), либо добавлять новые, начиная с 5-й строки.
- На будущее можно добавить:
  - Тонкую настройку соответствия конкретных полей (например, как именно формировать `Название объявления` или `Описание` из структуры товара).
  - Логику синхронизации `Номер объявления на Авито` обратно из выгрузок/отчётов Авито при повторной загрузке файла.
