## 0) Что считаем целью
- Поднять видимость в Яндексе по группам: «{бренд}+номер/OEM», «купить запчасть…», (в меньшей степени категории/инфо).
- Достичь за 3–6 месяцев: рост позиций + рост органического трафика и/или заказов.

## 1) База и контроль качества (1–3 дня)
1. Зафиксировать стартовые метрики в Яндекс.Вебмастере и/или из выгрузок:
   - количество проиндексированных страниц (хотя бы диапазон) и динамика за 2–4 недели;
   - разделы «Диагностика»/«Исключено»/«Дубли» и список доминирующих причин;
   - топ-20 запросов по кликам/показы по нужным тематикам (бренд+номер, купить).
2. Сделать 5–10 «эталонных» URL карточек товаров из реальных запросов и записать их ожидаемые сниппеты.

## 2) Карточки товаров (/part/): индексация, сниппет и разметка (ключевой приоритет)
1. Проверить, что для Яндекс-ботов реально отдаётся HTML с нужным title/description (а не дефолтный из `frontend/my-autoparts/public/index.html`).
   - Проверка через nginx rewrite/prerender endpoint.
2. Согласовать каноникал и заголовки:
   - как минимум убедиться, что для страниц вида `/part/{id}-{brand}-{article}` canonical указывает на полный URL;
   - для `/part/{id}` — в индексе их немного (вы так и выбрали), но каноникал/правила должны исключать дубли.
3. Разметка:
   - Product + Offer + Breadcrumb уже есть в `frontend/my-autoparts/src/pages/PartDetail/PartDetail.jsx` и серверной логике prerender;
   - дополнительно убедиться, что в JSON-LD корректно проставляются availability/price и что описание очищается от HTML.

## 3) Закрытие нецелевых URL (у вас selected: noindex для фильтров)
1. Каталогные страницы с параметрами (filters с query) не должны индексироваться.
   - Технически это достигается комбинацией: robots rules + meta robots noindex (если нужно) + корректный canonical.
2. Убедиться, что «мусорные» URL (поиск по каталогу/параметры сортировки/страницы без ценности) не дают дубли title/description.

## 4) Механика «404» и борьба с soft-404 (стабилизация индексации)
1. Проверить 3 сценария (важно после правок nginx/backend):
   - несуществующий URL → HTTP 404 (а не 200 index);
   - существующий публичный URL → HTTP 200;
   - `/part/…` удалённый/скрытый товар → 404.
2. После подтверждения сделать в Вебмастере «Переобход» для затронутых шаблонов.

## 5) Сайтом в целом: sitemap, отдача, корректные ссылки
1. Убедиться, что sitemap-источники обновляются и содержат правильные URL `/part/{id}-{brand}-{article}`.
   - У вас в sitemapindex есть `api/feeds/sitemap-products.xml` (динамический).
2. Внутренние ссылки на карточки:
   - цель — чтобы ссылки в результатах поиска/карточках в публичной части чаще вели на полный URL с брендом+артикулом (это повышает релевантность сниппета и снижает дубли).

## 6) UGC/Отзывы: усиление CTR без блога
1. Раз вы показываете отзывы в публичном виде, зафиксировать:
   - на каких именно страницах и как часто обновляются;
   - можно ли вывести рейтинг/количество отзывов в structured data (если на фронте это уже делается — закрепляем).
2. Тюнинг сниппета под CTR:
   - title уже нацелен на «бренд+номер»;
   - description сделать максимально «коммерчески понятным» (доставка/наличие/гарантии) без переспама.

## 7) Отслеживание и итерации (еженедельно)
- Каждые 7 дней:
  - проверка динамики «Исключено/Дубли/Ошибки» в Вебмастере;
  - проверка 5–10 эталонных URL (сниппет, каноникал, HTTP code);
  - корректировка приоритетов: если по запросам «купить…» растёт, расширяем семантику; если проседает — проверяем тексты/цены/доступность.

## 8) Что не делаем (чтобы уложиться в ваши ограничения)
- Не уходим в большой блог (вы выбрали no_blog).
- Не делаем массовый SSR/пререндёр для категорий, раз серверные изменения допустимы только частично.
- Не покупаем ссылки (бюджета на это нет) — упор на контент/техническую релевантность/правильные URL.
