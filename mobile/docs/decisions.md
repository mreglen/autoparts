# Этап 0 — зафиксированные решения

Дата: 06.11.2026. Источник: обсуждение + ответы на уточняющие вопросы.
Карта этапов: `mobile/docs/PLAN.md`.

## Решено

| # | Решение | Последствия для плана |
|---|---|---|
| 0.1 | Проект живёт в этом репозитории, папка `mobile/app` | Общий CI и один источник правды по API; `node_modules`, `.expo`, `ios/build`, `android/app/build` — в `.gitignore` и в исключения синхронизации OneDrive (делаем на этапе 2) |
| 0.2 | Expo SDK пинится на старте, апгрейд — отдельным окном после пилота | Никаких плавающих диапазонов версий (правило проекта: зависимости не моложе 7 дней) |
| 0.3 | Чтение — TanStack Query поверх клиента, сгенерированного из OpenAPI; формы — локальный стейт/слайсы | Требование офлайн-чтения (0.5) ложится на Query-персистентность, а не на самописный кэш |
| 0.4 | Токены — secure-store; фильтры и черновики форм — персистентное хранилище (аналог `usePersistedPageFilters` и черновика заказ-наряда на вебе) | Выбор конкретной библиотеки ограничен 0.6: до покупки подписки Apple приложение запускается в Expo Go, а там доступны только модули из набора Expo |
| 0.5 | **Офлайн v1 — по максимуму: чтение без сети во всех разделах роли, запись только онлайн** | Слой кэша + таблица протухания + маркировка устаревших данных — этап 3 (офлайн-движок), а не «потом»; прогон таблицы актуальности — этап 19 |
| 0.6 | **Подписки Apple Developer нет.** iOS делаем, но до покупки подписки — только через Expo Go на своём iPhone | iOS-сборки физически негде делать (MacBook Air 2017 не тянет нужный Xcode). Android-релиз не ждёт Apple; APNs/TestFlight/App Store отложены; push-канал делим на «Android сейчас, iOS после подписки» |
| 0.7 | **Google Play Console не покупаем.** Публичной публикации в v1 нет | Android — подписанный APK со ссылкой с сервера + экран «есть обновление» (этап 17); iOS-раздачи нет вовсе, только Expo Go; `FCM` живёт без Play Console, `APNs` — после подписки Apple |
| 0.8 | **v1 = полное покрытие роли «автосервис»**, включая полную форму создания и редактирования заказ-наряда | Критический путь: этап 10 (форма) и 11 (планировщик). Роль «клиент» — вторая очередь (этап 21) |
| 0.9 | **Пилот — свой автосервис, свои сотрудники, рабочие прод-данные.** Условие заказчика: ничего не потерять и не сломать веб | Бэкенд-работы только аддитивные, с дефолтом «как сегодня»; перед включением write-экранов — бэкап БД и `uploads`; каждый новый экран сначала read-only; feature-флаги на бэкенде не заводим |
| 0.10 | **Авторизация в v1 — email + пароль** (в том же поле работает телефон), как на сайте | Этап 4 не ждёт OTP. `sub` → `user_id` и отказ от fuzzy-склейки клиентов остаются блокерами роли «клиент» (этап 21), а не v1 |
| 0.11 | Нужен один реальный бюджетный Android для замеров, конкретную модель не выбирали | Меряется на этапе 19, покупать надо до этапа 2; достаточно любого телефона 2–3 лет на 3–4 ГБ RAM |

## Что из этого следует для бэкенда

Порядок работ этапа 1 не меняется, но из 0.5 и 0.9 вырастают три требования:

1. Ответы списочных эндпоинтов обязаны содержать достаточно метаданных, чтобы клиент честно показывал
   возраст данных: пагинация и `total` — обязательны, а не «по вкусу».
2. Ни одна правка не меняет дефолтное поведение (0.9), поэтому пагинация вводится как опциональные
   `limit/offset`, а не как новое обязательное поле.
3. Эндпоинт версии приложения и раздача APK (0.7) существуют с самого начала: без сторов пилот иначе
   не обновляется.

## Закрыто после обсуждения

- Play Console — не покупаем, публичной публикации в v1 нет (0.7).
- Пилот — свой автосервис на рабочих прод-данных, с условиями «не потерять» и «не сломать веб» (0.9).
- Объём офлайн-чтения — все разделы роли «автосервис» (0.5).
- Авторизация v1 — email + пароль (0.10).

## Остаётся открытым (не блокирует этап 1)

1. **Конкретный бюджетный Android для замеров** (0.11). Нужен до этапа 2, потому что на нём меряется
   стоимость недельной сетки и метрик текста; пока достаточно любого телефона 2–3 лет на 3–4 ГБ RAM.
2. **Когда (и покупается ли) Apple Developer** (0.6). От даты зависит возврат этапа 16 (APNs) и любая
   iOS-публикация; до неё iOS-ветка проверяется только через Expo Go на своём iPhone.
3. **Максимальный возраст офлайн-данных по экранам** — входит в этап 3 как отдельное решение, а не в этап 0.
